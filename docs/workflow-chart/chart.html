The q Workflow

Notes for the next edit

  • This page never ships. The chart gets screenshotted into q's README; the README's prose does the introducing. Everything a cold reader needs must live inside the SVG — nothing on this page around it. After editing, regenerate both README images with docs/workflow-chart/screenshot.py.
  • Three section panels (entry points, workflow loop, docs) carry the layout: panels are tinted --bg on the frame's --surface, node boxes are --surface so they pop. Work edges connect boxes and cross panel borders freely; the docs reads and writes attach to panel borders on both sides — whole sections read and write the docs, not one stage or one row. The single exception is upstream PRs, fed by project docs directly, because overrides originate there. Cross-panel labels live in the whitespace between panels, each above its own line.
  • Arrow language (no legend, by choice): solid ink moves work; dashed reads the docs; green writes them. Green is reserved for the docs circuit — the two write edges, project docs' border, and its tag line.
  • Two box namespaces: entry boxes are skills (mono names, one-line purpose); loop boxes are stages, with emojis marking the actor — 🤖 agent, 🧑 human, 🧑↔🤖 both, 🚀 shipping. That is why /q:address-feedback labels its return arc instead of sitting inside the 🧑 PR review box it answers — a skill line inside a human box would misname the actor. Box titles are capitalized; skill names and q stay lowercase.
  • Inbound arrows mark the entries: each entry skill takes an arrow from outside whose label names what arrives — from above for triage and implement, from the left for review, which sits below the plan row. The label and the box's one-line purpose must not repeat each other.
  • The three loop feeds merge into one bus before entering investigate: which skill started the run stops mattering once it has.
  • Pill chips mark forks: a pill on an edge names one of the paths a choice can take — quick fix vs plan first out of implement, ship mode vs local mode out of adversarial review (ship drops straight to the PR; local passes the human's local review first, whose revision requests return to discuss). A box whose edges carry pills drops its one-line purpose rather than restate them. The paired short arrows between execute and adversarial review are the fix loop.
  • Precedence lives inside the docs panel: project docs win on conflict, then extensions, then q — the stack order says so, top down.
  • Specs are dimmed (opacity + "WIP") until the specs surface ships; un-dim the column when it does.
  • Deliberate omissions: the maintenance and setup skills (/q:update-docs, /q:groom-docs, /q:install, /q:sync, /q:update, /q:drive, and friends) — the chart shows the work loop, not the catalog; the entry skills' own conversations (/q:create-plan runs investigate and discuss too, but drawing it into the loop would say it opens PRs).
